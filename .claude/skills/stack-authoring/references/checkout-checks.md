# Checks this checkout runs on shipped files

Read this before you write or edit anything under a stack's `files/` or `adapters/`. Shipped files live inside this repository, so this repo's lint, typecheck and tests read them too.

- Biome lints and formats files under `packages/cli/registry/` with this repo's config (double quotes; `mobile-expo` and the `clerk` fragment use single quotes). `packages/cli/biome.json` turns on Tailwind directives for registry CSS and relaxes the unused-import rules for `.svelte`, `.astro` and `.vue` files, since markup uses what the script imports. It turns off Biome's formatter and assists for stacks whose project formats with Prettier (`astro-blog`, `nestjs-api`, `nextjs`, `nuxt`, `sveltekit`, and the fragment overlays for `astro-blog`, `nextjs` and `sveltekit`), so this repo's formatter never rewrites code the project's own lint step checks. A stack that switches formatter moves in or out of that list. Name a shipped `biome.json` `biome.json.tmpl` so it isn't read as a nested config. Run `bun run lint` from the repo root.
- `packages/cli/tsconfig.registry.json` includes every shipped `.ts` file (`.d.ts` too, but not `.tsx`) and typechecks it against this repo's installed packages (`effect`, Bun and Node types), with `lib` ES2023 and no DOM. A file that imports a package this repo doesn't install (React, Next.js, SvelteKit, Astro, Expo, Tauri), uses browser globals, or declares ambient types fails `bun run typecheck`. Exclude such files by directory in the config's `exclude` (the framework app's source and test trees, its `.d.ts` files), with a comment naming the reason. `exclude` only filters `include`: an included file that imports an excluded or `.tsx` file pulls it back in. So exclude the whole tree that imports framework code, keep the files checked today (shared `scripts/`, hook tests, `typescript-api`-style Effect code), and confirm with `bun run typecheck`.
- `.tmpl` files escape both checks above. Prefer relative imports over `@{{package_scope}}/...` workspace names where the stack allows it. The fresh-scaffold proof is the only check of templated code.
- `validate` warns on a version literal in the config files it knows (`core/validate/version-sensitive.ts::VERSION_SENSITIVE`: package, TypeScript, Python, Go and Cargo manifests, Maven and Gradle builds, the build, test and release tool configs it names, linters, Docker, workflows), and the bundled registry must stay warning-free (`tests/bundled-registry.test.ts`). It doesn't read `tauri.conf.json`, Expo's `app.json`, `rust-toolchain.toml`, Wrangler config, `next.config.*`, `svelte.config.js`, `react-router.config.ts`, `drizzle.config.ts` or `.prettierrc`. It reads Compose files but flags only a three-part version, so an image tag such as `postgres:17` passes. Check those by hand. A manifest's own version needs two parts (`version = "0.1"`) or none where the format allows it; ship no `requires-python`, `rust-version` or `engines` line.
- Every shipped file a tool reads is exercised by a verify step. Docs, editor settings (`.vscode/`, `.editorconfig`) and PR templates are exempt.
- A `files/.gitignore` applies to this repository too, so a shipped path its patterns match (`build/`, `out/`, `next-env.d.ts`) passes the proof but never reaches a commit. Check `git status --ignored --porcelain packages/cli/registry/stacks/<id>` and add negations to the shipped `.gitignore` where needed, as `typescript-api`'s does.
- The search card's digest covers the entry, so every `STACK.md` edit makes `search-stale` warn until the card is restamped (`../search-card.md`). Restamp after your last edit, including on a card you wrote or rewrote.
- The stack body stays under 2,000 words and each composed brief under its budget: run `bun run dev validate --brief <id> --sandbox`, then once with each default and optional fragment.
- Tests pin composed output and brief prose. Find the ones naming the stack with `grep -rln '<id>' packages/cli/tests` (among them `gate-findings.test.ts`, `library-qa-*.test.ts`, `brief.test.ts`, `registry-hooks.test.ts`, `agent-harness.test.ts`, and for some stacks `registry-api-harness.test.ts`, `codex-api-harness.test.ts` and `mobile-dev-*.test.ts`). When the conversion moves a rule from prose into a shipped file, move the assertion with it onto the scaffolded file (`readFileSync` on the project the test scaffolds); never delete or loosen one. Regenerate `tests/fixtures/bundled-brief-digests.ts` keys as its header says.
