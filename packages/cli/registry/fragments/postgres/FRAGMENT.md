# PostgreSQL

Read `docs/guidance/postgres/index.md` before implementation for Compose, commands and the private database test harness. Migrations are the only schema source: tests run them, never create a schema from models.

## What to add

Use the Compose services, environment and Makefile targets in the guidance file; verify calls `db-up`, `db-migrate` and `db-down`.

<!-- stacks:when stack=python-react -->
**Backend.** The Python project is `backend/`; `compose.yaml` and `.env.example` stay at the repo root.
<!-- stacks:end -->
<!-- stacks:when stack=python-api -->
**Backend.** The Python project is the repo root, beside `compose.yaml`. Replace the shipped MemoryNotes behind NoteStore with a SQLAlchemy store and a notes migration; keep its route contract. `/healthz` is the shipped DB-free liveness route; use it wherever the shared guidance below calls the base route `/health`.
<!-- stacks:end -->

SQLAlchemy async typed-declarative models in `app/db/models.py` with a shared `Base` and a constraint naming convention (stable autogenerated names). Alembic from its async template in `migrations/`; `env.py` reads the URL from `Settings` (never `alembic.ini`), `target_metadata = Base.metadata`. The async engine is created in the lifespan on `app.state`; a `get_session` dependency yields an `AsyncSession` per request. Add `database_url` to `Settings`. Keep the dependency's annotations available at runtime: FastAPI inspects them, even when the dependency lives outside the API directory and the linter suggests moving imports.

**Health.** `/health` stays DB-free; add `/health/ready` running `SELECT 1`, returning 503 with the error envelope when the DB is down.

## Test harness

Use the guidance file's per-run template and per-file database harness; each run owns only its named databases. Test concurrent sessions, failed migration cleanup and a route round trip on a real database.

<!-- stacks:when with=ci-github -->
## CI

Add a Postgres service container (same image, healthcheck, `TEST_DATABASE_URL` pointed at it) to the job that runs the Python tests, and run `make db-check` before the tests.
