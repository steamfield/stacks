# Astro site + Effect API development

`dev:api` runs Node from the repository root, so relative `STATIC_DIR` and log paths resolve there; `dev:web` enters `apps/web` with `bun run --cwd`. `dev:bg` and `dev:stop` invoke `scripts/dev-bg.ts start` and `stop`. `dev:api` runs `apps/api/src/platform/node.ts` with watch mode and `--env-file-if-exists=.env`. `dev:web` passes `--ignore-lock` to keep Astro in the foreground under an agent. The Astro config reads `PORT_WEB`; the API reads `PORT_API`. `build` bundles the API for Node without inlining env, then builds Astro. `start` runs the bundle with the same env-file flag. The wrapper owns both servers and capped logs (`dev.log`, `dev.jsonl`, `server.jsonl`), preserving the previous run. Agents use `dev:bg`, `dev:stop`, `dev:status` and `logs --help`.

The API and Vitest run on Node. Never `bun test` and never `--bun`. Bun doesn't pass its loaded `.env` to a Node child. `@astrojs/check` can lag the newest TypeScript major: if it rejects the installed TypeScript, install the previous major and record it under Build workarounds. If content types or route types look stale, delete `apps/web/.astro/`.
