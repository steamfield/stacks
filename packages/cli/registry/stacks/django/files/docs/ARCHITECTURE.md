# Architecture

## Request path

gunicorn (`config/gunicorn.py`) loads `config.wsgi:application`. Middleware runs in the order
`config/settings.py::MIDDLEWARE` lists it:

1. `core.middleware.RequestLogMiddleware`: keeps a valid `X-Request-ID` or makes one, binds it to
   structlog's context, and logs one `request` line (method, route pattern, status, duration)
   after the response. `/healthz` logs at debug; 5xx at error.
2. Django's security middleware (HTTPS redirect, HSTS, nosniff), then whitenoise for `/static/`.
3. Sessions, common (host validation), CSRF, auth, messages, clickjacking.

URLs: `config/urls.py` mounts each app's `urls.py`, `/healthz` and `/admin/`. Unknown paths render
`templates/404.html`; an unhandled exception renders `templates/500.html` (standalone, so it
can't fail on a broken base layout) and `django.request` logs the traceback.

## Settings

`config/env.py::load` reads every deployment setting from the environment once, validates it and
fails startup with the variable's name. `DJANGO_ENV=production` turns DEBUG off, requires
`DJANGO_SECRET_KEY`, and turns on secure cookies, the HTTPS redirect (`/healthz` exempt), HSTS,
JSON logs and hashed static files. Everything else in `settings.py` is fixed code.

## Data

SQLite at `DJANGO_DB_PATH` (default `var/db.sqlite3`), in WAL mode with immediate transactions so
several gunicorn workers can write. Tests use a fresh test database per run (per xdist worker).
Migrations are generated by `makemigrations` and applied by `migrate`: `make dev` and `make start`
run it locally; a deployment runs it once as a release step before new code takes traffic.

## Logging

`config/logging.py` routes structlog and the standard library through one formatter: readable
lines in development, JSON lines on stdout in production. Exceptions keep class and frames but
never their message or local variables.

## Apps

- `accounts`: the custom `User` model. It exists from the first migration so it never has to be
  swapped in later.
- `core`: cross-cutting code. `CoreConfig.ready` configures structlog.
- `notes`: the example feature. Copy its shape for new apps (`.claude/skills/add-model` when using
  Claude Code).
