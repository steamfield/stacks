# Xcode project rules

- `project.yml` (XcodeGen) is the project. The `.xcodeproj` is generated by `make project` and gitignored; a hook denies edits inside it. Adding a source file needs no spec change, since targets include their folders, but run `make project` before building.
- Build settings every target shares live in `Config/Shared.xcconfig`; per-target settings live under that target in `project.yml`. Never lower a warning or analyzer setting, and never turn off `GCC_TREAT_WARNINGS_AS_ERRORS` or `SWIFT_TREAT_WARNINGS_AS_ERRORS`.
- Target names `App`, `AppTests` and `AppUITests` and the module name `App` are fixed: `App-Swift.h` and the Makefile depend on them. Rename the product with `INFOPLIST_KEY_CFBundleDisplayName` and the bundle identifier instead.
- Simulator builds never sign (`CODE_SIGNING_ALLOWED=NO` in `scripts/xcodebuild.sh`). Signing for a device or the App Store is a separate configuration the user sets up.
- The deployment target and `SWIFT_VERSION` are recorded in `project.yml`; raise them deliberately and record why in AGENTS.md.
