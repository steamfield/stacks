# Phaser game guidance

Read these before changing the matching code. They apply to every coding agent; Claude's rules and skills link here.

- [architecture](architecture.md): the logic/engine split, determinism, saves, input and the shell.
- [engine](engine.md): how Phaser fits the split, scaling, assets and the APIs that changed between Phaser majors.
- [testing](testing.md): Vitest, scenarios, smoke tests and what each asserts on.
- [verification](verification.md): the check, see and e2e loop before calling work done.

`DESIGN.md` describes the game itself: its loop, controls, scenes and launch parameters. Keep it current when gameplay changes.
