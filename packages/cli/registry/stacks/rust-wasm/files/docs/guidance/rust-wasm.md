# Rust and WebAssembly

How code in this package is written. The shipped code follows every rule here; keep to them when extending it. [The JavaScript API](../js-api.md) lists what the package exports and how that may change.

## Layout

- One package at the repository root, inside a workspace (`[package]` and `[workspace]` in the same `Cargo.toml`), built as `cdylib` (the `.wasm`) and `rlib` (for native tests).
- `src/lib.rs` is the JavaScript API: every `#[wasm_bindgen]` item, the `typescript_custom_section` with the TypeScript shapes of plain objects, and the `extern "C"` types that name them. Nothing else in the crate uses `#[wasm_bindgen]`.
- Logic lives in plain Rust modules (`src/slug.rs`, `src/options.rs`, `src/error.rs`) with no `wasm-bindgen` types, so native `cargo test` covers it fast. They are `pub(crate)`: the Rust side is private.
- `src/js.rs` is the boundary: decoding options from JavaScript values, encoding results as plain objects, and turning `Error` into a thrown `SlugError`. It exports nothing.
- `pkg/` is generated by `make build` (wasm-pack and the wasm-bindgen CLI). Never edit it; change `src/lib.rs` and rebuild.
- `consumer/` is a separate JavaScript project that installs the packed package by name and tests it on Node. It has its own `package.json`, `bun.lock` and `tsconfig.json`.
- Dependencies are added with `cargo add <crate> --features <list>` (and `bun add -d` inside `consumer/`), never by editing version strings. `Cargo.lock` and `consumer/bun.lock` are committed and only the tools write them; checks run with `--locked` and `--frozen-lockfile`.

## The boundary

- Arguments are JavaScript primitives (`&str`, numbers, `bool`) or an options object typed by an `extern "C"` type with `typescript_type`, decoded with serde-wasm-bindgen. Optional arguments are `Option<T>`, so `undefined` and `null` both mean the default.
- serde-wasm-bindgen ignores keys a struct doesn't name, even with `deny_unknown_fields`. Each options struct lists its keys (`Options::KEYS`) and `src/js.rs` rejects any other, naming it in `field`.
- Results are primitives, an exported class, or a plain object built with `serde_wasm_bindgen::Serializer::json_compatible()` (objects, not `Map`s) and typed with `typescript_type`. Keep the TypeScript in `TYPES` and the Rust struct in step: field names are camelCase on both sides.
- Doc comments on exported items become the comments in `pkg/*.d.ts`; write them for JavaScript callers and name the error codes under `# Errors`.
- An exported struct is a class holding WebAssembly memory. JavaScript frees it with `free()` or `using`; document that on each new class.

## Errors

- One `thiserror` enum (`src/error.rs`) for the logic, each variant with a stable `code()` string. Exports return `Result<T, JsValue>` and `?` converts the error into a JavaScript `Error` named `SlugError` with `code` and, where known, `field`.
- Codes are part of the API: adding one is a minor change, renaming or removing one is breaking. A new code goes in `SlugErrorCode` in `TYPES`, the README's error table and `docs/js-api.md`.
- Never panic across the boundary. A panic in wasm aborts with `RuntimeError: unreachable` and leaves the module's state undefined; clippy denies `unwrap`, `expect` and `panic!` outside tests.

## What wasm32 can't do

`wasm32-unknown-unknown` has no operating system. These compile but fail or panic at run time, so the shipped code uses none of them:

- `std::time::Instant` and `SystemTime::now()`; take a timestamp from JavaScript as an argument instead.
- `std::thread`, `std::fs`, `std::net`, `std::process` and `std::env`.
- Printing: `println!` goes nowhere. The library never logs; return information to the caller.

A crate that needs randomness or time on wasm32 needs its JavaScript feature enabled (getrandom's `wasm_js`, for one); check the crate's docs before adding it.

## Lints and formatting

`[workspace.lints]` in `Cargo.toml` is the lint policy: `unsafe_code` forbidden, `missing_docs` and `unreachable_pub` denied, clippy's default set denied and `pedantic` warned (denied by `-D warnings`), plus `unwrap_used`, `expect_used`, `panic`, `todo`, `dbg_macro`, `print_stdout` and `print_stderr`. `clippy.toml` allows unwrap, expect and panic in tests. `make clippy` runs for the native target and for wasm32, since `cfg(target_arch = "wasm32")` code compiles only there.

- Fix a lint rather than silencing it. When a lint is wrong for one item, use `#[expect(<lint>, reason = "why")]` on that item; `allow_attributes` denies `#[allow]`.
- `cargo fmt` formats the Rust code; there is no `rustfmt.toml`, so the edition comes from `Cargo.toml`.

## Testing

- Unit tests sit in `#[cfg(test)] mod tests` beside the logic and run natively with `cargo test` (`make test`).
- `src/web_tests.rs` runs the exports compiled to wasm32 in Node with wasm-bindgen-test (`make test-wasm`): JavaScript values in, thrown `SlugError`s out. Each export gets a case, including one for each error code it can throw.
- `consumer/test/` imports the package by name after `make test-js` packs `pkg/` and unpacks the tarball into `consumer/node_modules/`, then typechecks against the generated `.d.ts` and runs on Node's test runner. It is the only test of what npm users install.
- Iterate with `cargo test <name>`; run `make lint test test-wasm test-js` before finishing.
