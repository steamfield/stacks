# R2. Seed data that looks right on the site

Priority P0. Depends on R0. Evidence: `seed-quality.md`. Works in `stacks-api`.

## Outcome

The pages a judge clicks (home, a popular stack, a sparse stack, `/deps/`, a few dependency
pages, the trending view) show believable data, and R5 has the exact flags to generate the
same data in production. Fix only what's visible on those pages.

## Read first

- `stacks-api/docs/telemetry.md` (seed section), `plans/archive/phases/phase-4.2g-seed-telemetry-2026-10-30.md`
  dated lines.
- Code: `stacks-api/scripts/seed/{index.ts,profile.ts,events.ts,simulate.ts}`.
- Tests: `apps/api/tests/seed-active-profile.test.ts`, `seed-dependencies.test.ts`,
  `seed-profile-regressions.test.ts`.

## Ground rules

- Write only to your own paths: `STACKS_DB_PATH=.dev/data/r2-<name>.sqlite
  STACKS_ARCHIVE_DIR=.dev/data/r2-<name>-archive`. Never `.dev/data/seeded.sqlite` (what
  `prod:seed` ships) or `.dev/data/active.sqlite` (another session's run).
- Always pass `--profile active --seed 1 --through <YYYY-MM-DD>`; the default `--through` is
  yesterday.
- A distribution change bumps `activeProfile.version` (`"active-3"` now).
- Don't touch publication thresholds.

## Steps

1. Look first. If the in-flight active run (R0 step 4) has finished (`complete: true`), serve
   it read-only with `STATIC_DIR=<index> STACKS_DB_PATH=.dev/data/active.sqlite
   STACKS_ARCHIVE_DIR=.dev/data/active-archive PORT_API=0 bun run dev:stats`. Otherwise build
   the index (`bun run build:index --out <scratch>/r2-index --previous none --unsigned
   --include-unproven` in `quickstack/packages/cli`) and seed a small sample:

   ```sh
   STATIC_DIR=<scratch>/r2-index STACKS_DB_PATH=.dev/data/r2-sample.sqlite \
   STACKS_ARCHIVE_DIR=.dev/data/r2-sample-archive \
   bun run seed --profile active --seed 1 --days 21 --through 2026-10-27
   ```

   Build the site against it (R4 step 5) and walk the pages listed under Outcome.
   In `seed-quality.md`, write one line per page: what looks wrong to a reader.

2. Fix what step 1 found, in this order, stopping when the pages read right:
   - Dependency pages mostly suppressed: raise how many projects report common packages
     within the existing eligibility rules, so at least five packages (including `react` and
     one scoped package) publish and at least one stays suppressed.
     Test: `seed-dependencies.test.ts`.
   - Nonexistent majors (majors are hash-generated in `scripts/seed/events.ts:308-329`): add
     a small hand-written table of real majors per seeded package in
     `scripts/seed/dependency-majors.ts`, from one `npm view <pkg> versions --json` pass
     (date it in a comment). Test: no generated major falls outside the table.
   - Failures all at install: pick the failing step from the steps the stack's manifest
     actually has, weighted, so stack pages show install, test and at least one other step.
     Test: `seed-profile-regressions.test.ts`.
   - Any other visible oddity from step 1 (a negative or absurd time-to-green, an empty
     trending view): fix it at the generator and add a regression case.
   Keep the existing rising, falling, new-entry and regression stories.

3. Re-seed the sample with the change and re-walk the pages. Record before and after for
   each line in step 1.

4. Write the production flags in `seed-quality.md` under "For R5":
   `--profile active --seed 1 --days 120 --through <YYYY-MM-DD>`, the profile version, and the
   wall time of the in-flight active run (R0 step 4) as the runtime estimate (about 46
   minutes per HANDOFF).

## Done when

- [ ] Scoped seed tests pass, with a case per fix.
- [ ] Every page from step 1 has a before and after line, and none still reads wrong.
- [ ] `seed-quality.md` has the R5 flags and runtime estimate.
