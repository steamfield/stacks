### Finding: dev script can terminate unrelated processes

**Severity: high. Owner: mobile-expo recipe.** `packages/cli/registry/stacks/mobile-expo/files/scripts/dev.sh.tmpl` calls `reap_all` before starting and during cleanup. It uses broad `pkill -f` patterns for workspace dev commands and kills every process listening on the selected API port and fixed Metro port 8081, including unrelated projects. Expected: fail clearly when a port is occupied and stop only processes started by this invocation. The parent safely reproduced the exact shipped `reap()` function against an independently started, owned sacrificial listener on an ephemeral port: it logged a kill and the listener exited on SIGTERM without any ownership record. Source inspection establishes the broader `reap_all` and fixed-port behavior; that full script was not executed to avoid harming other work. Evidence is in `cli-evidence/mobile-reap-component.json`. In the temporary project the script was replaced with an owned-process-only launcher for subsequent work; this did not change product source.

**Medium-severity setup side effect, owner: tauri-react recipe.** The shipped `make install` runs `rustup toolchain install` with no self-update suppression. On this host the requested 1.99.0 toolchain was already installed, but rustup automatically updated its global manager from 1.29.1 to 1.29.2 during that command. This global update was unintended and outside the authorized temporary project scope. The captured install excerpt is `runtimes-evidence/tauri-install-rustup.txt`. Rustup's own help documents `--no-self-update`; the temporary Makefile was changed to include it for subsequent runs. The machine was not changed back without authorization. A setup target should install the requested toolchain without silently updating the user's toolchain manager.
