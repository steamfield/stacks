# React Router and OpenRouter chat manual QA

Status: the base and added app both reached green full verification and ran locally. This is not a complete independent audit of every recipe requirement: several implementation and test requirements listed below remain missing or untested. All work used the packed current-source CLI, isolated CLI state, and a disposable project; no real provider key, account, paid request, deployment or push was used.

Findings and recovery:

- **Recipe/agent adapter guidance, medium:** the added brief asks the agent to read app-owned Claude rules; `DESIGN.md` specifically points to `.claude/rules/openrouter-chat/styling.md`, and `biome-plugins/styling.grit` diagnostics name it. Reproduce with the Codex-only add above: that file and the Claude rules directory are absent. Expected referenced guidance to exist or be linked to an equivalent. The Codex app skill and DESIGN document did ship and contain substantial guidance, so this is a broken specific reference, not absence of all guidance. Source owners: `packages/cli/registry/fragments/openrouter-chat/FRAGMENT.md`, `files/DESIGN.md.tmpl`, and `files/biome-plugins/styling.grit`. Recovery: read the native skill, DESIGN, and plugin; apply the plugin and correct generated shadcn styling warnings.
- **Agent implementation error, recovered:** initial SDK-generated user message IDs failed the brief's UUID validation; provide `generateId: crypto.randomUUID` and rerun the browser flow. Initial Stop showed an interruption but reload lost the partial reply. A server-side cancellation and partial save, then a browser test that waits for its completion, fixed the observed text-only case. Early reruns accidentally used an older production build; rebuilding before browser testing resolved that test setup error.
- **Agent implementation gaps, not attributed to the recipe:** recorder and replay fixtures, paid eval scripts/scoring, multi-page model/cache and TestClock retry/refill coverage, complete upstream status matrix and structured-output retry behavior were not implemented. Export does not include all requested model/usage metadata. Error UI retry policy beyond the tested 401, clipboard fallback, fallback detection, interrupted tool-state persistence, and all concurrency/abort edges were not fully exercised. The app's green manifest therefore does not establish full recipe compliance. Paid recordings/evals and live provider calls were not attempted; no fabricated fixtures were used. The temporary README recorded these missing scripts and the credit-limit prerequisite.
- **Verification coverage:** no production or app steps were skipped, but checks cannot detect the missing recorder/evals or all behavioral requirements above. The observed gaps belong to this temporary implementation; whether the recipe or CLI should enforce additional checks requires a separate design decision.

Raw sanitized CLI results, browser output, and test output are in [web-app-evidence](web-app-evidence/). The first app verify predates the final README, extraction no-key handling and error test; the final all-green result includes those changes. The browser Stop test was run against a newly rebuilt production app. No project code or registry changes were retained.

Cleanup: closed the owned browser, confirmed no listener on ports 15300, 15301 or 15302 and no process with the scratch path, then removed the project, isolated CLI state, cache and browser installation.
