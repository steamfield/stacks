# Web chat follow-up

The updated React Router and OpenRouter chat composition reached green verification with an unchanged manifest. The final `verify --all --json` reported 17 passed steps, none failed or skipped, and a full tamper check. That result covers the commands the temporary app supplied; it does not independently establish every requirement in the acceptance document. The implementation and audit limits below remain.

The run used the built Node CLI from the gap-fixes worktree at base commit `1e65551c277194e89530ed1bd99e73b54f1b7521` plus its then-uncommitted registry changes. A fresh project used the sandbox preset, Codex adapter and default base fragments `agent-ops`, `ci-github`, `claude-harness`, `effect-schema`, `effect` and `git-hooks`. Adding `openrouter-chat` also added required `openrouter-ai`; the add reported no pending merges. The prior report was not edited.

## Findings and limits

- The generated brief at scaffold time stated that verify “separately enforces” the acceptance matrix, but the CLI runs an agent-authored test file and does not inspect whether its assertions cover the matrix. This was a wording/verification-boundary issue in `packages/cli/registry/fragments/openrouter-chat/FRAGMENT.md`; the parent was notified and has since revised that wording. The new mandatory commands did run here, and the actual assertions are retained in the evidence directory.
- The prior Codex-only broken styling-rule reference is resolved in this scaffold: `docs/guidance/openrouter-chat/styling.md`, the native skill, DESIGN and the acceptance document were written and read.
- The temporary app still did not implement the entire brief. Its base lacks the complete tagged-error architecture, some hook regression coverage and full CI execution. The live recorder, atomic replacement against existing real fixtures and live eval were not executed; real-provider formats and costs are unverified. The eval's live concise-answer scoring is shallow, and its per-model report does not aggregate all requested cost/token and verdict totals. These are temporary implementation gaps, not established recipe defects.
- Explicitly untested or incomplete: disconnect during a pending tool call, all malformed/network upstream and model-discovery browser states, full fallback behavior with real provider aliases, clipboard API absence, retry timing under TestClock, and some accessibility and stream-concurrency edges. The direct program and browser tests above do not cover those paths. The separate e2e model-discovery failure had a warm-cache limitation. The production browser tests used a local provider stub; they do not certify model quality or deployment.
- The verifier's 0 skipped count refers to manifest steps. The separately inspected Vitest result has four real-fixture replay tests skipped, as required when recordings are absent. A green command cannot establish assertions that the agent never wrote.
